# Лабораторная работа 6. Коллекции и дженерики

Проверка: `./mvnw -pl lab06 test`

## Что реализовано

| Класс | Назначение |
|-------|------------|
| `Box<T>` | контейнер для одного значения типа `T` (`get`, `set`) |
| `Stack<T>` | учебный стек на `ArrayList<T>`; `null` запрещён, `pop` и `peek` пустого стека бросают `NoSuchElementException` |
| `ProjectTask`, `TaskStatus` | минимальная модель из ЛР 5 (поля `id`, `title`, `category`, `estimatedHours`, `status`) |
| `TaskAnalytics` | подсчёт по статусам, уникальные значения `category`, сортировка |

## Выбор коллекций

| Задача | Результат | Реализация | Почему |
|--------|-----------|------------|--------|
| Число задач по статусам | `Map<TaskStatus, Integer>` | `EnumMap` | Нужно соответствие «ключ → число», значит `Map`. Ключи — константы `enum`, поэтому `EnumMap`: значения лежат в массиве по `ordinal()`, без хеширования, операции за O(1), обход идёт в порядке объявления констант. `HashMap` тоже подошёл бы, но порядок обхода у него произвольный. Статус, которого нет в данных, записи не получает. |
| Уникальные категории | `Set<String>` | `TreeSet` | Главное требование — отсутствие повторов, это контракт `Set`. В `TreeSet` повтором считается элемент, для которого `compareTo` вернул 0 (для `String` это совпадает с `equals`); `HashSet` определял бы повтор через `equals`/`hashCode`. `TreeSet` выбран ради предсказуемого алфавитного порядка в отчёте: у `HashSet` порядок не гарантирован, `LinkedHashSet` хранит порядок первого появления. Цена — O(log n) на добавление вместо O(1). |
| Отсортированные задачи | `List<ProjectTask>` | новый `ArrayList` | Важен порядок, повторяющиеся значения допустимы, значит `List`. Строится копия, поэтому исходный список не изменяется. `List.sort(Comparator)` — устойчивая сортировка, O(n log n). |

### Сравнение в `Comparator`

Порядок: сначала по `estimatedHours` по возрастанию, при равенстве — по `id`. Для сравнения используются `Integer.compare` и `String.compareTo`, а не вычитание: разность `a - b` может переполниться и дать неверный знак. Идентификаторы сравниваются как строки, поэтому `"T-10"` идёт раньше `"T-2"`.

## Сложность операций стека

| Операция | Сложность | Пояснение |
|----------|-----------|-----------|
| `push` | O(1) амортизированно | добавление в конец `ArrayList`; редкое расширение массива «размазывается» по операциям |
| `pop` | O(1) | удаляется последний элемент, остальные не сдвигаются |
| `peek` | O(1) | чтение последнего элемента |
| `size`, `isEmpty` | O(1) | размер хранится в списке |

Вершина стека — **конец** списка: если бы вершиной был индекс 0, каждый `push` и `pop` сдвигал бы все элементы (O(n)).
Класс `java.util.Stack` не используется (он устарел и построен на синхронизированном `Vector`); в прикладном коде для стека обычно берут `ArrayDeque`.

## Допущения

- `Box<T>` допускает `null`, `Stack<T>` — нет (по условию).
- Методы аналитики не принимают `null`-список и `null`-элементы (`NullPointerException`).
- Raw types и приведения типов не используются.
